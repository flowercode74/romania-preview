# بررسی فنی پروژهٔ رومانیا

## نظر کلی

پروژه پایهٔ خوبی برای یک نمونهٔ قابل‌بازی دارد: رابط فارسی، قلمرو شش‌ضلعی، ساخت‌وساز زمان‌دار، اقتصاد، پژوهش، ترکیب نیرو، نبرد، لشکرکشی، آموزش و ذخیرهٔ محلی به هم متصل شده‌اند. آزمون‌ها دریافت تکراری پاداش، تکمیل دوبارهٔ صف، مسیرهای غیرمجاز و چند سناریوی مهاجرت ذخیره را پوشش می‌دهند.

ضعف اصلی، تجمع مدل، قوانین، رندر و رابط در یک فایل بزرگ و انباشته‌شدن اصلاحات CSS بود. این ساختار توسعه و بررسی تغییرات را دشوار می‌کرد. حجم زیاد تصاویر، نام‌های نامفهوم یا غلط، مستندات ناسازگار و نبود مسیر ادامهٔ ذخیره نیز مشکلات عملی بودند. نسخهٔ مرتب‌شده این موارد را هدف گرفته است؛ بازی همچنان نمونهٔ محلی است.

## دامنهٔ بررسی

آرشیو اولیه ۸۲ فایل داشت: ۶۵ تصویر، دو HTML یکسان، JavaScript حدود ۶۴۲۰ خط، CSS حدود ۵۳۷۹ خط، شش مجموعهٔ آزمون و مستندات. بررسی شامل ساختار، ارجاع‌های ثابت و تولیدشدهٔ تصاویر، چرخهٔ ورود و ذخیره، بارگذاری تصاویر، بخش‌های اقتصاد و صف‌ها، رابط و گزارش نبرد، رندر قلمرو و نقشه، آزمون‌های موجود و مستندات بود. پیش از تغییر، هر شش مجموعهٔ آزمون موفق شدند.

## تغییرات تحویلی

| موضوع | تغییر |
|---|---|
| منبع JavaScript | تقسیم به ۱۳ فایل با موضوع و ترتیب مشخص؛ ساخت خروجی یکتا در یک محدودهٔ خصوصی |
| منبع CSS | تقسیم به پنج بخش؛ حفظ ترتیب قواعد و تقدم اصلاحات فعلی |
| ابزار توسعه | ساخت، بررسی ارجاع‌ها، اجرای آزمون‌ها و سرور محلی بدون وابستگی نصب‌شدنی |
| ورود | نمایش ادامهٔ ذخیرهٔ معتبر و تأیید پیش از شروع بازی تازه |
| ذخیرهٔ خراب | خواندن ایمن هر ذخیره و امکان مهاجرت ذخیرهٔ قدیمی در صورت خرابی JSON جدید |
| دادهٔ تولید | جلوگیری از مقدار غیرمتناهی یا نامعتبر در مخزن ساختمان پس از بارگذاری |
| بارگذاری تصویر | استفادهٔ مجدد از Image کش‌شده؛ حذف درخواست و Decode جدا در لودینگ؛ حذف URLهای تکراری |
| پایان لودینگ | پایان امن پس از خطای تصویر یا سقف انتظار ۱۵ ثانیه، با حفظ fallback رندر |
| مسیرهای تصویر ذخیره‌شده | اعتبارسنجی مسیر محلی و تبدیل نام‌های قدیمی تصاویر دشمن به نام جدید |
| گزارش نبرد | ایمن‌کردن درج مسیر تصویر و چند مقدار ذخیره‌شده در HTML |
| ساختار assets | `itemimages` به `items`، `helper` به `characters`، GIF به `animations` و کمپ به `buildings` |
| نام‌ها | اصلاح `cavarly`، `swordmen`، `toturialbanner`، حروف بزرگ و نام‌های مبهم دیوار، پس‌زمینه و سازه |
| اطلس | حذف ارجاع به `tiles.png` مفقود؛ استفاده از اطلس موجود `tiles-v2` |
| حجم تصویر | تبدیل ۶۲ PNG به WebP بدون اتلاف، با مقایسهٔ ابعاد و پیکسل‌ها؛ حفظ GIF و JPG |
| مستندات | جایگزینی راهنماهای متناقض با راهنمای جاری، گزارش، نگاشت تصاویر و جدول استخراج‌شده از منطق اجرا |

کلیدهای ذخیره، شناسه‌های gameplay و مقادیر بالانس عمداً تغییر نکرده‌اند. فایل‌های منبع بخش‌بندی شده‌اند؛ استقلال کامل ماژول‌های مدل و UI هنوز برقرار نشده است و به بازطراحی قراردادهای داخلی نیاز دارد.

## حذف‌ها

- `romania.html`: نسخهٔ یکسان `index.html`؛ نقطهٔ ورود اکنون یکتا است.
- `assets/helper/Helper3.png`: تصویر جایگزین مشاور، بدون ارجاع در کد، قالب و انتخاب ظاهر.
- هفت تابع بدون مصرف: `drawImageCover`، `getTerrainAtlas`، `drawHexFallback`، `clipCastleCourtyard`، `armyActionMarkup`، `grantPendingTutorialRewards` و `researchMarkup`.
- آرایهٔ بدون استفادهٔ `REPORTS`.
- راهنماهای به‌روزرسانی قدیمی با ادعاهای ناسازگار دربارهٔ تصاویر، سقف انبار، درمان و قابلیت‌ها؛ اطلاعات جاری در راهنمای جدید آمده است.
- PNGهای جایگزین‌شده با WebP؛ نسخهٔ اصلی در آرشیو ارسالی کاربر باقی است.

آزمون‌ها، جدول بالانس، تصاویر فعال و نسخهٔ آمادهٔ اجرای CSS/JS حذف نشده‌اند؛ این‌ها بخش‌های کاربردی پروژه‌اند.

## محدودیت‌ها و مسیر توسعه

۱. **نسخهٔ آنلاین:** سرور، احراز هویت، پایگاه داده و چندنفره وجود ندارند. API محلی `RomaniaGame` و قواعد فصل، اجرای واقعی سرور محسوب نمی‌شوند. در نسخهٔ چندنفره، منابع، نبرد و پایان صف باید توسط سرور معتبر محاسبه شوند.

۲. **ذخیرهٔ محلی:** localStorage و زمان دستگاه قابل تغییرند. اعتبارسنجی فعلی برای سلامت داده مفید است، اما ضدتقلب نیست. اتصال حساب باید بعد از پیاده‌سازی واقعی احراز هویت فعال شود.

۳. **نگهداری کد:** بخش‌بندی و ساخت خروجی، قدم عملی برای نظم پروژه است. برای توسعهٔ بزرگ‌تر، انتقال قوانین خالص اقتصاد، پژوهش و نبرد به ماژول‌های مستقل، و ایجاد قرارداد مشخص میان مدل و رابط، قدم بعدی است.

۴. **CSS:** فایل فعلی اصلاحات تاریخی و قواعد دارای تقدم دارد. ترتیب آن‌ها حفظ شده است. ادغام گستردهٔ قواعد هم‌نام، بدون مقایسهٔ بصری واقعی می‌تواند چیدمان را عوض کند؛ چنین ادغامی در این تحویل انجام نشده است.

۵. **کارایی:** کش تصاویر و کاهش حجم بهبود یافته‌اند. نقشه از Canvas، کش و شاخص مکانی استفاده می‌کند. FPS، حافظهٔ واقعی موبایل و زمان ورود روی دستگاه اندازه‌گیری نشده‌اند؛ بهبود عددی آن‌ها ادعا نمی‌شود.

۶. **بررسی رابط:** Chromium اجرایی در محیط موجود نبود. آزمون‌های منطق و HTTP موفق‌اند، اما جای آزمون تصویری و لمس روی مرورگر واقعی را نمی‌گیرند. Drag، زوم دو انگشتی، ورود/ادامه، دیالوگ شروع تازه، پنل‌های نظامی و بازگشت پس از خروج باید روی گوشی نیز بررسی شوند.

۷. **بالانس:** آزمون‌ها چند قرارداد عددی مانند قدرت ساختمان‌ها و سکهٔ روزانه را کنترل می‌کنند. تعادل نهایی فصل و اقتصاد به Playtest و دادهٔ رفتار بازیکنان نیاز دارد.

۸. **فونت:** فونت‌های Google در HTML باقی‌اند؛ در حالت بدون اینترنت، fallback مرورگر استفاده می‌شود. خود بازی برای اجرای محلی به سرویس حساب آنلاین متصل نیست.
